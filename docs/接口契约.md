# 接口契约

> 本文定义**跨模块、跨时间的稳定契约**：CLI 命令面、库边界、输出格式、落盘格式。
> 这些一旦有别的东西依赖上（三个月后的你、别人的脚本、下一阶段的评分器），改动成本就很高。
> 行为规格见 [实施规划.md](实施规划.md)，验收标准见 [开发排期与验收.md](开发排期与验收.md)。

## 1. CLI 命令面

包名 `e8004`，入口 `e8004.cli:app`（typer）。**这是完整清单，不要自行发明命令。**

```
# —— 元 ——

e8004 diagnose  [--chain NAME]                # 候选 0x8004 地址身份鉴定（发现了两组平行注册表）
e8004 bootstrap [--chain NAME|--all]          # T0：地址验证 + 部署区块

e8004 snapshot-state --chain NAME --snapshot ID [--limit N] [--start-id N]

e8004 fetch-uri      [--chain NAME] [--limit N] [--dry-run]
e8004 probe          --round N [--chain NAME] [--limit N] [--dry-run]

# —— 入库（短暂持锁，几秒钟）——
e8004 load <stage>                             # spool JSONL → DuckDB，幂等 upsert

# —— 纯函数 stage（零网络访问）——
e8004 parse-cards [--snapshot ID]
e8004 analyze concentration|dedup|hosts|crossval|all --snapshot ID
e8004 funnel  --snapshot ID
e8004 report  --snapshot ID
```

**未实现（P2，见 开发排期与验收 §2）**：`fetch-feedback-files`、`verify-payments`、
`trace-funding`、`export`、`run-all`。全量跑用仓库根目录的 `run_full.sh`。

**全局选项**：`--config DIR`（默认 `config/`）、`--db PATH`（默认 `data/e8004.duckdb`）、`--log-level`、`--json`（结构化输出，供脚本消费）。

**退出码**：`0` 成功；`1` 一般错误；`2` 配置/参数错误；`3` **DoD 断言失败**（如 T8 交叉验证不通过、T2 的 `owner_matches_logs` 超阈值）。CI 和 `run-all` 靠退出码 3 强制停下，而不是靠人自觉。

## 3. `e8004.probe` 库契约（最重要的一条边界）

按 实施规划 §11，这个包三个月后要独立发布。**现在就必须守住边界，否则第二阶段是重写而不是扩展。**

### 边界规则

- **不许 import duckdb、不许 import 本仓任何 stage 模块、不许读 `config/chains.toml`。**
- 依赖只允许：`httpx`、`aiodns`、标准库。
- 验收：`python -c "import e8004.probe"` 在没装 duckdb 的干净虚拟环境里必须成功（T5 DoD）。

### 公开 API

```python
from e8004.probe import ProbeConfig, ProbeTarget, probe_many

@dataclass(frozen=True)
class ProbeTarget:
    endpoint: str                 # 完整 URL
    declared_kind: str            # "web" | "A2A" | "MCP" | "OASF" | "ENS" | "DID" | "email"
    ref: str | None = None        # 调用方的关联键，原样回传（本仓传 "chainid:agentid:svcidx"）

async def probe_many(
    targets: Iterable[ProbeTarget],
    config: ProbeConfig,
    on_result: Callable[[dict], Awaitable[None]] | None = None,   # 流式回调，用于边跑边落盘
) -> list[dict]: ...
```

`on_result` 是必需的设计：全量探测跑几小时，结果必须边产生边落盘，不能攒在内存里等最后返回。

### 输出 schema v1.0

```json
{
  "schema_version": "1.0",
  "ref": "1:31204:0",
  "probed_at": "2026-08-20T03:11:22Z",
  "target": {
    "endpoint": "https://agent.example.com/mcp",
    "declared_kind": "MCP",
    "host": "agent.example.com",
    "port": 443,
    "scheme": "https"
  },
  "layers": {
    "dns":  { "outcome": "ok", "elapsed_ms": 12,
              "resolved_ips": ["203.0.113.7"], "ip_class": "public", "error": null },
    "tcp":  { "outcome": "ok", "elapsed_ms": 88, "error": null },
    "tls":  { "outcome": "ok", "elapsed_ms": 140, "tls_ok": true,
              "error_kind": null, "not_after": "2026-11-02T00:00:00Z" },
    "http": { "outcome": "ok", "elapsed_ms": 210, "status": 200,
              "server": "nginx", "body_bytes": 1187, "error": null },
    "proto":{ "outcome": "ok", "elapsed_ms": 305, "kind": "mcp_streamable", "ok": true,
              "version": "2025-06-18", "server_name": "example-agent",
              "server_version": "0.4.1", "tool_count": 3,
              "capabilities": { "tools": {}, "resources": {} }, "error": null }
  }
}
```

**`outcome` 取值**：`ok | fail | skip | rate_limited | blocked`。

**三条 schema 纪律**：

1. **没有 `verdict` / `live` 字段，这是刻意的**（CLAUDE.md 硬约束 16）。「是否算活」由消费方判定——本仓在 `s08_funnel` 用 SQL 做，判定口径随时可改并重算历史。探测器一旦开始下结论，raw/derived 分离就破了。
2. **`ip_class`** 取值：`public | private | loopback | reserved | literal`。`literal` 指 endpoint 直接写 IP 而非域名。非 `public` 的都是「根本没打算对外服务」，不是「服务器挂了」。
3. **TLS 证书问题记录但 `outcome` 仍可为 `ok`**。`error_kind` 取 `expired | self_signed | hostname_mismatch | other`。证书过期的服务是活着的，把它算成死的是错的。

新增字段 → `1.x`；删改字段或改语义 → `2.0`。

## 4. 核心模块签名

```python
# e8004/rpc.py —— 自适应步长 + 重组保护
class RpcClient:
    async def call(self, method: str, params: list) -> Any: ...
    async def get_logs(self, addresses: list[str], from_block: int, to_block: int,
                       topics: list | None = None) -> list[dict]:
        """步长过大导致的错误由本方法内部折半重试并收敛，调用方不感知。
        收敛值通过 self.converged_range 暴露，由 s02 回写 chain.max_log_range。"""
    async def find_deploy_block(self, address: str) -> int:
        """在 [0, latest] 上二分 eth_getCode，约 25 次调用。需要 archive 节点。"""
    async def safe_head(self) -> int:
        """finalized 标签；不支持则 latest - confirmations。扫描上界一律用它，不用 latest。"""

# e8004/probe/limiter.py —— 三层限速。调用方必须经由 acquire 才能发请求
#
# 【两类目标要用两个 limiter 实例，不要混用】
#   打别人的 agent 服务器  -> per_host_interval_s=3.0（伦理红线，不许放宽）
#   打公共 IPFS 网关       -> per_gateway_rps（网关是为高吞吐设计的基础设施；
#                             按 3 秒/请求会让 9 万个 CID 跑 40 小时，
#                             而且并不会让任何人更舒服）
class DualLimiter:
    def acquire(self, host: str, ip: str | None = None) -> AsyncContextManager[None]: ...
    def block_host(self, host: str, reason: str) -> None: ...
    def is_blocked(self, host: str) -> bool: ...
    @property
    def stats(self) -> dict: ...      # dry-run 与 status 用

# e8004/spool.py —— 网络 stage 的落盘缓冲，绕开 DuckDB 单写者锁
class Spool:
    def __init__(self, stage: str, run_id: str): ...
    async def write(self, record: dict) -> None: ...   # 追加 JSONL，每 N 条 fsync
    def close(self) -> None: ...

# e8004/db.py
def connect(path: str, read_only: bool = False) -> duckdb.DuckDBPyConnection: ...
def migrate(conn) -> None: ...                          # 执行 docs/schema.sql，幂等
def load_spool(conn, stage: str) -> int: ...            # JSONL → 表，按主键 upsert，幂等
def get_cursor(conn, stage: str, chain_id: int) -> str | None: ...
def set_cursor(conn, stage: str, chain_id: int, cursor: str) -> None: ...
```

## 5. Spool JSONL 格式

每行一条记录，**必须自带足够信息使入库无需查库**：

```json
{"_stage":"scan-logs","_chain_id":1,"_run_id":"20260820-0312","_seq":19402,
 "block_number":24839901,"block_hash":"0x..","log_index":7,"address":"0x8004a1..",
 "topic0":"0x..","data":"0x.."}
```

- 下划线前缀字段是 spool 元数据，入库时剥掉。
- `_seq` 单调递增，用于检测截断（进程被杀时最后一条可能不完整——**入库时遇到 JSON 解析失败的最后一行直接丢弃并告警，不要报错退出**）。
- **入库后不删除 JSONL**：它是 raw 层的一部分，跟数据集一起发布。

## 6. 测试策略

### fixture 的先有鸡问题

T1 的 DoD 要求「用**真实链上 payload** 做解码 fixture」，但 payload 要先扫才有。所以提供一个专门命令：

```bash
e8004 dump-fixtures --chain 1 --count 5 --events Registered,NewFeedback,MetadataSet,Transfer
# → tests/fixtures/logs/<chain>_<event>_<n>.json（原始 eth_getLogs 响应，原封不动）
```

**要求**：`NewFeedback` 的 fixture 里必须至少有一条 `value < 0`、一条 `valueDecimals > 0`、一条 `tag1` 非空（用于验证 `string indexed` 取的是 data 段而不是 topic 哈希）。凑不齐就扩大 `--count` 继续找。**这三个是最容易写错且错了不报错的地方。**

### 目录与要求

```
tests/
├── fixtures/logs/          # 真实链上原始日志
├── fixtures/cards/         # 真实 + 手工构造的畸形 agent card
├── test_abi.py             # 解码器（用真实 fixture）
├── test_limiter.py         # 限速实测，见下
├── test_parse.py           # card 解析与 schema 校验
├── test_funnel.py          # 漏斗 SQL 的黄金用例（小型合成数据集）
└── conftest.py
```

- `test_limiter.py` 必须起一个**本地 HTTP 服务器记录到达时间戳**，实测「同 host 最小间隔 ≥3s、最大并发 =1、200 host 并发时全局 ≤10 req/s」。这三条是伦理红线的代码化，不能只靠 code review。
- `test_funnel.py` 用手工构造的小数据集，断言每层单调不增、`declared_inactive` 不被计入 L3 失败。
- 网络测试一律打本地服务器，**CI 不许出网**。
